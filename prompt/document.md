## 📋 7. README.md & Documentation Workflow (MANDATORY)

### 🎯 Purpose

`README.md` must act as a **living document**, updated continuously to reflect:

- Project purpose
- Architecture
- Features
- Detailed feature workflows (business + developer view)

Every change to functionality, logic, or behavior must include a README update.

---

### 🧱 README Structure (Required)

1. **Project Summary**
   Brief overview of what the project does and its target users.

2. **Architecture Overview**

   - Folder structure (short version)
   - Key principles (components, common, pages, theme)

3. **Feature List**
   List of key features (title + one-line description)

4. **Feature Workflows (for each feature)**

   - **Business Flow**: what happens from the user’s or business perspective.
   - **Developer Flow**: what components, hooks, and utils are involved; data and API flow.
   - **State & Storage**: how state is managed and persisted.
   - **Edge Cases**: how failures or errors are handled.

5. **Setup & Local Run**
   Steps to run locally.
